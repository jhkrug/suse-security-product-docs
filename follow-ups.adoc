= Follow-ups for the SUSE Security product docs

Open questions and known issues found while building this repository from
the upstream community repository. Remove an item when it is done.

== Values to confirm

* *Admission controller image tags.* In `admission-controller/version-1.39`,
  `{release-tag}` (`v1.38.2`) is the upstream tag. The product file assumes the
  product image tags are the same. `{default-policy-server-image-tag}` uses it
  to build the `dp.apps.rancher.io` image reference. If the product image tags
  have no leading `v`, add a separate image tag attribute.
* *Release tags and chart versions.* The product `variables.adoc` of every
  component dev version copies `{release-tag}` and `{chart-version}` from
  upstream. Confirm that the product versions are the same. The updatecli job
  that bumps them upstream writes only to `community-specific/variables.adoc`.
  The sync to this repository must also bump the product files.
* *Network Enforcer chart.* `{network-enforcer-helm-chart}` is a guess,
  `oci://dp.apps.rancher.io/charts/suse-security-network-enforcer`. No page
  uses it at the moment.

== Build and publishing

* *Sync: GitHub Action.* `scripts/sync.py` plans and applies a sync,
  including the items below, and lists what needs a person. Next: a GitHub
  Action that runs `apply` on a schedule, builds the site, and opens a sync
  pull request with the report as its body.
* *Sync: translations.* Only `admission-controller` 1.34 to 1.39 have
  translations (de, es, fr, ja, pt, zh). The `nav:` list of the `antora.yml`
  of each of these versions also lists the language navs. The sync must keep
  them. When the English pages change, the sync must also copy new English
  pages into the language modules as placeholders, add them to the language
  navs, and remove pages that no longer exist in English. It must also
  refresh the existing placeholders, which are copies of the English pages,
  when those English pages change.
* *Sync: language variables partials.* Each language module of the
  translated versions has its own copy of `partials/variables.adoc` and
  `partials/product-specific/variables.adoc`. The translated pages include
  these copies, not the English files. The copies hold attributes, not
  translated text, and must be the same as the English files. When the sync
  changes an English file, it must copy it to all the language modules. If
  a copy is out of date, the translated pages get missing attributes or old
  values. Symlinks to the English files, as for `images`, could replace the
  copies if the translation process does not overwrite them.
* *Sync: moved pages.* When an English page moves, for example from
  `pages/howtos/` to `pages/product-specific/howtos/`, the rule above would
  remove the translated pages and add English placeholders. This loses the
  translations. The sync must detect moved pages and move the translated
  pages to the new path with `git mv`. It must also update the paths in the
  language navs and in the xrefs and image macros of the translated pages.
  The move of the Rancher how-tos in 1.35 to 1.39 was done this way by hand.
* *Sync: component titles.* The product `antora.yml` files differ from
  upstream in `title:`, and for translated versions in `nav:`. The sync script
  must keep these `title:` values:
** `docs/sbom-scanner/version-*/antora.yml`: `title: Vulnerability Scanner`
   (upstream `SBOM Scanner`).
** `docs/kw/version-*/antora.yml`: `title: SUSE Security` (upstream
   `Kubewarden`).

* *Mermaid diagrams in the publishing playbook.*
  `@sntke/antora-mermaid-extension` applies `subs` to the wrong value, so
  diagrams with `[mermaid,subs="attributes"]` render as the word "attributes".
  rancher/product-docs-common#102 (block processor) and
  SUSEdoc/dsc-style-bundle#88 (mermaid loader) fix this, and this repository
  uses them. `product-docs-playbook` still uses the sntke extension. Bump its
  submodules, replace the extension with
  `./product-docs-common/extensions/mermaid-block/mermaid-block.js` under
  `asciidoc.extensions`, and remove the package.
* *Publishing playbook.* `product-docs-playbook` builds the published site.
  When this repository goes live:
** Replace the `kubewarden-product-docs`, `sbomscanner-product-docs`, and
   `runtime-enforcer-product-docs` sources with one source for this repository,
   with the same start paths as `remote-product-playbook.yml`.
** It sets `build-type: product@` and the old `kw-build-type`. Check that no
   page overrides `build-type`.
** It indexes with `index_latest_only: true`. This repository uses `false`.
